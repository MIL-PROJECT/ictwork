# OMNIS — 정보통신 업무 통합 관리체계 (저장소: ictwork)

부대 운영 및 정보통신체계 운용 효율화 웹서비스.

| 구분 | 기술 |
|---|---|
| 백엔드 | Spring Boot 2.7.18, Kotlin 2.0.21, Java 17, Gradle (WAR) |
| 프론트엔드 | React 19, TypeScript, Vite, Tailwind CSS 4, pnpm (TailAdmin 템플릿 기반, `src/frontend/LICENSE.md`). 화면 디자인은 같은 팀 OMNIS의 디자인 체계를 따름 |
| DB | MySQL 8.0 (Flyway 마이그레이션) |

## 기능

정보통신상황실을 중심으로 부대 운영 현황과 정비·지원 요청 업무를 하나의 웹 체계로 처리한다. 조직·인원은 가상 데이터다(대대 ▸ 중대 ▸ 반).

### 역할과 권한

| 역할 | 범위 | 주요 권한 |
|---|---|---|
| 대대장·중대장·반장 | 역할 대상 부서와 하위 부서 | 범위 안의 업무 조회, 기본 결재 경로의 직위 결재자, 업무 현황 부서장 범위, 지시사항 올리기 |
| 부서 관리자 | 관리 범위 | 조직·인원·계정·역할 관리, 장비 관리부서 옮기기, 설치장소 관리, 업무 유형·양식과 장비·인원 추가 특성 만들기 |
| 시스템 관리자 | 체계 전체 | 체계 전체 조회, 부서 삭제, 기본 결재 경로 관리 |

- 역할은 "역할 + 대상 부서"로 주고 여러 개를 겸할 수 있다. 권한이 없는 메뉴는 보이지 않는다.
- 역할과 관계없이 누구나 업무를 요청하고, 소속 부서에 온 업무를 접수·처리하며, 소속 부서 장비를 등록·수정한다.

### 통합상황판

로그인하면 처음 열리는 화면(`/board`). 업무·정보통신 현황을 한 화면에 모아 보는 관제 화면이다.

- 지표 카드 4개(현황 전체·이번 달 완료·긴급 업무·진행 중 업무)와 통제 띠(내 부서 접수 대기·내 결재 차례·주의 현황·지연 업무·이번 달 요청/완료·오늘 근무)
- 카드 4개: 정보통신 현황, 업무 진행 현황(이번 달 완료율·진행 중 업무), 업무 접수 대기, 지시사항. 창 높이에 맞춰 행 수를 정하고 넘치면 쪽으로 넘긴다
- 줄이나 카드를 누르면 해당 화면·상세로 간다

### 일반

| 메뉴 | 기능 |
|---|---|
| 지시사항 | 부서장이 역할 대상 부서 명의로 지시사항(내용·그림)을 올린다. 직책마다 가장 최근 지시사항을 박스로 보이고, [기록] 탭에서 지난 지시사항을 본다 |
| 근무자 현황 | 부서별 근무표(야간 당직·교대근무 등)를 만들고 날짜별 근무자를 본다 |
| 정보통신 현황 | 부서 관리자가 현황 박스를 만들어 체계별 운영 상태(예: 기반통신체계 정상)와 정보통신 상황(CPCON·GPS 전파교란·위기경보단계 등)을 한눈에 보인다 |

### 업무

| 메뉴 | 기능 |
|---|---|
| 업무 현황 | 보는 범위의 처리 건을 상태별로 세고(접수 대기·계획·완료 등), 기간별 실적·사람별 투입 통계·부서별 비교 대시보드를 보인다. 보고서 모양으로 인쇄·PDF 저장하거나 엑셀로 내려받는다 |
| 달력 | 개인 일정(연·월·주·일, 본인만 봄)과 처리 건 작업 일정(월·주·일)을 달력으로 본다 |
| 등록된 업무 | 우리 부서 업무·요청한 업무·열람 업무 세 탭에서 처리 건을 상태·기간·유형으로 걸러 보고, 상세에서 계획·첨부·지시사항·결재 이력을 본다 |
| 업무 요청 | 받는 부서(여러 곳)와 부서별 업무 유형을 고르고, 유형마다 정해진 양식과 제목·장소·사유·담당자·희망일자·첨부파일을 채워 보낸다. 발송 결재를 거치게 할 수 있다. 받는 부서마다 처리 건이 하나씩 생긴다 |

**처리 흐름**: 요청 → 처리 건 접수 대기 → 접수(바로 접수 또는 접수 결재) 또는 반려·이송 → 계획(작업 기간·지원 인원·장비를 칸 단위로 1~20개) → 완료 결재 → 완료. 처리 건이 모두 끝나면 요청 상태가 정해진다. 자동 완료를 켜면 계획 기간이 끝날 때 체계가 완료 결재를 올리고 바로 끝내 완료한다.

### 결재함

| 메뉴 | 기능 |
|---|---|
| 업무 등록 | 요청 없이 우리 부서 업무(정비계획 등)를 등록하고 결재에 올린다 |
| 업무 접수 | 소속 부서에 온 접수 대기 처리 건을 바로 접수·접수 결재·반려·이송한다 |
| 업무 결재 | 내 차례인 결재를 승인·반려(사유 필수)하고, 처리한 문서를 본다 |
| 진행 중 결재 | 내가 올리거나 경로에 든 진행 중 결재를 보고, 회수·결재자 바꾸기·재상신(새 회차)을 한다 |

- 결재 문서는 발송·접수·완료 세 종류이고, 단계 구분은 검토·결재·전결·전대결·대결·공석이다.
- 결재 경로는 올릴 때 조직 트리에서 사람을 골라 쌓거나 기본 결재 경로를 불러와 정하고, 그 건에만 적용된다.

### 부서관리

| 메뉴 | 기능 |
|---|---|
| 조직도 | 체계 전체 조직과 사용 중인 인원(계급·연락처)을 트리로 본다 |
| 인원 | 소속 범위의 사용 중인 인원(부서·직책·계급·성명·연락처·배정된 업무)을 본다. 일일 병력 현황을 대신한다 |
| 장비 | 장비를 등록·수정·불용 처리하고, 반출 여부·현재 위치·사진·관련자료를 관리한다. 엑셀 일괄 등록·내려받기, 표에서 바로 고치기, 이전 입력값 추천을 지원한다. 업무 계획에 든 장비는 일정에 맞춰 반출 여부가 자동으로 바뀐다 |
| 구성도 | 장비를 배치하고 선·구역·도형·글상자·그림으로 네트워크 구성도를 그린다. 한 사람씩 편집(잠금), 저장할 때마다 판 기록, 사람·부서별 공유/편집 권한, 삭제·되살리기, PNG 저장·인쇄를 지원한다 |
| 문서함 | 부서마다 공유 문서함을 둔다. 폴더·파일 올리기·이름 바꾸기·옮기기, 사람·부서 공유, 휴지통(30일), 미리보기(PDF·그림·txt), 용량 상한(체계 500MB·문서함 50MB 기본)을 지원한다 |

### AI 질의응답

- 채팅 화면에서 체계 자료를 근거로 묻고 답한다. 답은 스트리밍으로 나오고 멈출 수 있다.
- 근거 자료는 질문할 때의 권한으로 정한다: 볼 수 있는 문서함 파일 본문(PDF·hwp·hwpx·docx·xlsx·pptx·txt)과 장비·업무·구성도 등 체계 데이터. 질의응답으로 볼 수 있는 범위가 넓어지지 않는다.
- 답마다 출처(파일 이름과 쪽·시트·슬라이드, 구성도·업무 이름)와 확인할 곳 링크를 보인다. 근거가 없으면 짐작하지 않고 "찾지 못했습니다"라고 답한다.
- 같은 대화의 앞 질문·답(최근 10번)을 이어 받는다. 질문은 한 번에 하나씩 차례로 처리한다.
- 같은 PC의 로컬 LLM(Ollama, 대화 `qwen3:8b`·임베딩 `bge-m3`)만 쓰고, 서버 설정으로 켜고 끈다.

### 알림·개인설정·관리

| 메뉴 | 기능 |
|---|---|
| 내 알림 | 상단바 종 단추로 오른쪽 서랍을 열어 요청 도착·처리 상태·결재 차례·결재 결과·지시사항 알림을 최근 50개까지 보고, 하나씩 또는 모두 읽음 표시한다. 새 알림은 화면 오른쪽 위에 잠깐 띄운다. 받을 알림 종류를 고른다 |
| 개인설정 | 본인 비밀번호를 바꾼다. 초기 비밀번호로 로그인하면 바꾸기 전까지 다른 기능을 쓸 수 없다. 화면 설정에서 언어·테마(이 브라우저에 저장)와 글자 크기 보통·크게(계정에 저장, 크게는 화면 전체 125%)를 고른다 |
| 조직관리 | 부서를 등록·이름 바꾸기·이동·삭제한다 |
| 인원관리 | 인원과 계정을 함께 등록·수정·전입·사용 중지하고, 역할을 주고 회수하고, 비밀번호를 초기화한다. 인원 추가 특성을 만든다 |
| 장비관리 | 관리 범위의 장비와 설치장소를 관리하고, 장비 추가 특성을 만든다 |
| 업무 유형 | 부서별 업무 유형(추가·이름 바꾸기·사용 중지·순서 바꾸기)과 요청할 때 채울 입력 양식을 만든다 |
| 결재 경로 | 부서·문서 종류별 기본 결재 경로를 단계 구분과 직위로 정한다 |

### 화면 공통

- 왼쪽 메뉴(접고 펼침), 상단바(현재 위치 경로·시계·밝은/어두운 테마·알림·사용자 메뉴). 어두운 테마는 글자·틀 위치는 같고 색만 바뀐다
- 목록은 아래 띠에서 건수·쪽 이동·페이지당 행 수를 고른다(10·20·30·50·100, 고른 값 기억)
- 상세 화면(처리 건·요청·결재 문서·구성도)은 [이전으로]와 상단 경로의 목록 이름으로 목록에 돌아간다
- 넓은 화면에서는 창 끝까지 넓어지고, 좁은 화면(휴대폰)에서는 메뉴가 서랍으로 열리고 넓은 표는 옆으로 밀어 본다
- 한국어·영어

## 폴더

```
src/
├─ backend/    # Spring Boot + Kotlin. 빌드 시 프론트를 함께 빌드해 WAR에 넣는다
└─ frontend/   # React SPA
```

## 실행

1. MySQL 8.0에 스키마 `ictwork`와 앱 계정을 만든다.
2. `src/backend/config/application.example.yml`을 같은 폴더에 `application.yml`로 복사하고 DB 비밀번호·공통 초기 비밀번호를 채운다 (Git 제외 파일).
3. 실행

```bash
cd src/backend
./gradlew bootRun --args='--spring.profiles.active=demo'
```

- `demo` 프로필은 시연 데이터(`db/seed`)를 함께 넣는다. 데이터 없이 띄우려면 프로필을 빼고 실행한다.
- `local` 프로필은 시연 데이터에 더해 AI 질의응답을 켠다 (같은 PC의 Ollama, `qwen3:8b`·`bge-m3` 필요).
- 프론트만 개발 서버로 띄우려면 `src/frontend`에서 `pnpm install` 후 `pnpm dev` (5173 포트).
- WAR 빌드: `src/backend`에서 `./gradlew bootWar` → `build/libs/ictwork-0.0.1.war`
