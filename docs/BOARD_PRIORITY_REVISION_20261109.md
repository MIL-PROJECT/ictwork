# 상황판 우선순위·지연 필터·높이 조정 (2026-11-09)

- 운영현황은 장애 → 중단 → 주의 → 점검 → 정상 순서이며 같은 상태에서는 운용률 오름차순이다. 사용자가 지정하지 않은 중단 상태도 숨기지 않고 장애 다음에 배치한다. 동률은 체계 코드와 ID로 정렬한다. 상황판과 전체 운영현황 목록에 같은 함수를 사용하며 API 원본 배열을 변경하지 않는다.
- 업무 진행 현황은 한 페이지 최대 3행이다. 실제 자료가 적거나 마지막 페이지인 경우 남은 항목만 표시한다.
- 상단 요약 카드는 기본/중간 화면에서 96px, 낮은 화면에서 80px를 기준으로 배치한다. 내용에 필요한 최소 높이는 보존한다. 1920×1080 검증에서는 기존 132px에서 96px로 줄어 하단 네 표가 각각 18px 높아졌다.
- 업무 진행 현황의 전체 보기로 연 부서 범위 목록에서 상태 버튼 옆에 지연 토글을 제공한다. 기존 `overdue=1` 주소 조건과 서버의 `WorkJudge.isOverdue`를 사용한다. 미완료이며 확정 종료일/시각을 지난 업무만 대상으로 한다. 다른 부서·상태·기간·상세 필터와 교집합이며 선택 시 페이지 번호만 초기화한다. 새로고침/뒤로 가기에도 주소를 따라 선택 상태가 유지된다. 백엔드와 저장 데이터는 변경하지 않았다.

## 검증

- 프런트엔드 Node 테스트 113개 통과. 상태 우선순위, 같은 상태의 운용률 정렬, 동률 순서, 원본 불변성과 빈 목록을 확인했다.
- 변경된 TypeScript/TSX 5개 파일 ESLint 및 TypeScript/Vite production build 통과.
- 실제 dev에서 1920×1080, 1366×768, 1366×660 배치를 측정했다. 요약 카드 내용 잘림 없이 업무 진행 현황 3행을 확인했다.
- 부서 관리자 화면에서 전체 보기 → 지연 선택 → 새로고침 → 지연 해제를 확인했다. 현재 진행 업무 47건에서 지연 교집합 15건으로 좁혀졌고 해제 후 부서/상태/기간을 유지하며 47건으로 복원됐다. 수치는 해당 검증 시점과 계정 범위에 한정된다.
- 로컬 증거: `output/dev/board-priority-revision/`, 로그: `output/dev/board-priority-*.log`.

Setup.exe 재생성, 설치 DB 변경, 백엔드 전체 테스트는 이번 프런트엔드 변경 범위에 포함하지 않았다.
