# 운영현황 통합 및 상황판 경보 영역 정리

2026-11-08, `feat/final-mvp`의 후속 UI 변경이다.

## 구성 판단

운영현황은 체계별 상태·운용률·변경 이력을, 기존 정보통신 현황은 CPCON·위기경보단계와 통신망별 대표 값·색·상세 자료를 관리한다. 서로 다른 데이터와 권한을 하나의 표나 수치로 합산하면 의미가 달라지므로, 사이드바는 **운영현황 하나**로 통합하고 화면 안에 **체계 운용 / 통신·경보**를 둔다. 기존 자료 모델·API·서버 권한을 그대로 사용한다.

통합상황판의 기존 혼합 요약줄은 제거했다. 업무 지연은 위쪽 업무 진행 카드의 기존 지연 수치·행에서, 오늘 근무는 기존 근무자 현황 메뉴에서 확인한다. 경보 영역에는 **통제 단계(CPCON·위기경보단계)**와 **주의 현황** 카드만 나란히 둔다. 지표별 상태색·부서, 주의 건수·우선순위·확인 시각·전체 조회를 유지하며 서로 관련 없는 업무 수치를 끼워 넣지 않는다. 두 카드에는 중립색 배경·둥근 모서리·간결한 링크를 사용한다.

업무 접수 대기 표의 번호·제목·우선순위·희망일 머리글에 수직 중앙 정렬을 적용했다. 화면 크기에 따라 높이가 바뀌어도 머리글은 행 가운데에 놓인다. 기존 열 너비·행 이동·페이지 이동은 유지한다.

## 경로·기능 호환

- 기본 `/operations` 및 `?view=systems`: 기존 체계 목록, 검색·상태 필터·등록·수정·상태 변경·삭제·이력.
- `/operations?view=signals`: 기존 통신 박스 목록·추가·고치기·담당자·상세 칸·첨부·지난 판·기록·개인 배치.
- `/ict-status?box=번호&tab=revisions` 같은 예전 링크는 통합 화면으로 이동하며 박스·상세 탭·해시를 보존한다. 작업공간은 `view`, 기존 박스 상세는 `tab`을 사용하므로 이름이 충돌하지 않는다.
- 두 보기 사이를 이동해도 주소의 체계 검색·상태·페이지 등 기존 조건을 보존한다. 뒤로 가기와 새로 고침에서도 주소를 다시 해석한다.
- AI 업무지원의 화면 이동과 서버가 반환하는 예전 `/ict-status` 경로를 통합 경로로 처리한다. 작성 세션의 경로도 함께 맞춰 이동 직후 종료되지 않도록 했다. 모델·백엔드·저장 로직은 변경하지 않았다.
- 통제 지표의 부서별 전체 조회, 표시 범위 전체 지표, 주의 전체 목록과 원본 상세 연결은 유지한다. 경보 집계에서 숨긴 자료·권한 밖 자료를 제외하며, 이전 확인값·오류·권한 회수·시간 초과 처리를 유지한다.

## 실행과 검증

새 Windows 폴더형 실행본은 `output/OMNIS-Unified-Operations-Windows-x64/OMNIS.exe`다. **resources를 포함한 폴더 전체**를 유지해야 한다. 기존 앱을 정상 종료한 뒤 실행하면 같은 사용자 프로필로 Java·MySQL을 자동 시작한다. 창을 닫으면 해당 서비스도 종료한다. 설치 프로그램이나 다른 PC 시험을 새로 수행했다는 의미는 아니다.

확인 순서는 다음과 같다.

1. 로그인 후 사이드바에서 별도 정보통신 현황 메뉴가 없어지고 운영현황 하나만 있는지 확인한다.
2. 운영현황의 체계 운용에서 상태·운용률·이력을, 통신·경보에서 CPCON·통신 박스·상세와 관리 동작을 확인한다.
3. 통합상황판에서 통제 단계와 주의 현황이 분리되고, 그 영역에 지연 중 업무·오늘 근무가 섞이지 않는지 확인한다.
4. 업무 접수 대기 머리글의 중앙 정렬과 페이지 이동을 확인한다.

`verify-operations-unified.cjs`는 독립 합성 프로필에서 실제 API와 UI로 한 메뉴·두 보기·조건 유지·예전 상세 주소·지난 판·권한을 확인하고, 시험에서 만든 박스만 추가/숨김/복원/삭제한다. 사용자 프로필에는 이 변경 시험을 수행하지 않는다. `verify-board-roles.cjs`는 네 계정의 기존 체계/박스 권한과 통합 화면을 함께 비교한다. `verify-board.cjs`는 경보 우선순위·503/403/시간 초과·복구 및 18개 화면 배치 조합을 확인한다. 인쇄·엑셀·업무 요청·접수·계획·결재·반려·등록대장 복귀·재시작은 기존 전체 회귀에 포함한다.

근거는 `output/operations-unified/`에 저장한다. 실제 사용자 자료의 읽기 검증은 `current-profile/`, 성공한 새 프로필 전체 검증은 `verified2/`, 서버 코드·API 보존 근거는 `integrity-result.json`에서 확인한다. AI 모델 추론 자체는 시연 프로필에서 활성화하지 않는다.

이번 결과: TypeScript·프런트엔드 108개 테스트·스크립트 구문 검사가 통과했다. ESLint 오류는 0개이며 AssistContext의 기존 fast-refresh 경고 3개는 남아 있다. 새 프로필에서 두 차례 기동·정상 종료·데이터 유지, 전체 업무·결재 회귀, 네 계정의 통합 화면 권한, 18개 상황판 배치, 통계 상단 조건·엑셀 저장·인쇄 CSS 검증이 통과했다. 접수 대기 머리글 네 개의 수직 중심 오차는 모두 0px이었다. 실제 사용자 자료는 체계 38개·정상 30개·운용률 79%·이력 3개가 유지됐다. 보호 대상 소스 320개와 WAR의 서버 코드·라이브러리 1190개 파일은 변경 전과 동일하다. 앞선 시험 대기 조건 보완 과정의 실패 기록도 별도 디렉터리에 보존했다.
