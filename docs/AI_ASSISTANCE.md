# AI 업무지원: 기획과 적용 범위

기획 기준: ictwork `feature/fault-report`의 `50efdcf`. 최종 작업에는 팀원의 최신 `f46e1d6`까지 포함했다. 사용자가 기획을 먼저 확인한 뒤 업무 현황 요약·유사 고장 사례·증상 분석을 함께 개선하도록 선택했다.

## 참고한 OMNIS 기능

OMNIS의 [업무별 AI 지원 화면](https://github.com/MIL-PROJECT/OMNIS/blob/96d84910367961ce3e0914852663f29e5dad355c/src/renderer/src/AiManagement.tsx), [기능별 출력 규칙](https://github.com/MIL-PROJECT/OMNIS/blob/96d84910367961ce3e0914852663f29e5dad355c/src/main/ai/PromptCatalog.ts), [모델 실패 시 대체 처리](https://github.com/MIL-PROJECT/OMNIS/blob/96d84910367961ce3e0914852663f29e5dad355c/src/main/ai/AIOrchestrator.ts)를 참고했다.

ictwork의 기존 자료 색인·검색·권한 검사·대화 저장·SSE·로컬 Ollama 연결을 유지한다. Electron/SQLite 구조나 외부 AI 제공자 설정을 이식하지 않는다.

## 사용자 흐름

기존 AI 질의응답 상단에서 지원 기능 선택 → 입력·기간 확인 → 같은 대화 안에서 결과 확인 → 자유 질문으로 전환해 이어 묻기. 새 페이지나 업무 처리 단계를 추가하지 않는다.

| 기능 | 입력 | 결과와 기준 |
| --- | --- | --- |
| 업무 현황 요약 | 소속 부서 기준, 조회 시작·종료일 | 기존 업무 현황 도구의 집계값과 동일 조건 링크. 실적은 선택 기간, 미완료·기한 지남은 현재 기준 |
| 유사 고장 사례 | 체계·장비명과 증상 | 기존 우리 부서 업무 범위의 최근 완료 업무 최대 300건에서 제목·업무 유형을 비교. 관련 완료 사례 최대 3건, 요청 내용·업무 기록·관련 표현·상세 링크 |
| 증상 분석 | 장비·증상·발생 시점·영향·이미 한 조치 | 관련 완료 기록, 근거에 따른 AI 검토 의견, 부족한 정보에 대한 확인 질문 최대 3개 |

- 검색은 설명 가능한 문자열 비교이며 PC·컴퓨터·피씨, 켜지지 않음·전원 같은 대표 표현을 연결한다. 알려진 장비 종류가 있으면 같은 장비군의 후보를 찾고 고장 질문에는 대여·행사 지원 기록이 섞이지 않게 한다. 일치도가 낮은 결과로 3건을 억지로 채우지 않는다. 의미 검색이나 통계적 확률이라고 표시하지 않는다.
- 조회 기간은 시작일부터 1년 이내다. 역순·잘못된 날짜·지원하지 않는 기능은 질문 저장 전에 거절한다.
- 완료율은 기존 업무 현황처럼 기간 내 완료 / (기간 내 완료 + 현재 미완료)다. 분모가 없으면 집계 대상 없음을 표시한다.
- 조치 결과 전용 항목이 없는 현재 데이터 구조를 유지한다. 지시사항을 조치 성공 기록으로 바꾸어 표시하지 않는다.
- 양식의 텍스트 답은 게시된 항목명을 붙여 보여준다. 내부 선택지 코드, 일정 항목, 연락처 항목을 사례 설명으로 나열하지 않는다.

## 답변의 근거와 실패 처리

- 수치·사례·출처·링크는 서버의 기존 조회 기능에서 만든다. 모델이 업무 ID나 링크를 만들지 않는다.
- 세 지원 기능의 검토 의견은 실제 조회 결과에 맞춰 서버가 제시한 선택지 안에서만 고른다. 비교 자료 없이 성과·인력·긴급 대응 수준을 평가하거나 완료 상태를 조치 성공으로 단정할 수 없다. 증상 분석의 추가 질문은 모델이 현재 입력의 부족한 확인 항목을 보고 작성한다.
- 증상 분석의 추가 질문에는 현재 입력과 부족한 확인 항목만 전달한다. 과거 사례의 IP·인원 등을 현재 신고의 사실로 오인하지 않게 한다.
- 모델 출력은 JSON 구조, 항목 수·길이, 새로운 숫자, 요약 선택지 준수 여부를 확인한 뒤 표시한다.
- 관련 사례가 없으면 사례를 만들지 않고 구체적인 장비명과 증상 입력을 안내한다. 근거가 없으면 분석 의견도 추가하지 않는다.
- 모델 연결 실패·잘못된 출력에는 체계 조회 결과와 기본 확인 질문을 남기고, AI 검토 의견을 받지 못했음을 표시한다.
- 조회 조건에는 AI 검토 포함 여부를 기록한다. 출처는 기존 메시지와 함께 저장하고 이어 묻기에서 기존 권한 검사를 적용한다.
- AI 기능 자체가 꺼져 있으면 기존처럼 모든 AI API가 404이며, 대체 처리로 이를 우회하지 않는다.

## 다른 기능에 미치는 영향

- 변경: AI 화면·질문 API의 선택적 입력·AI 질문 처리·기능별 조회 보조 서비스·한국어/영어 문구.
- 재사용: 업무 현황 집계, 우리 부서 업무 목록/상세, 출처 접근 검사, 대화와 메시지 저장, 질문 대기·중지.
- 업무 요청·접수·작업 계획·달력·결재의 처리 규칙 및 DB 스키마는 변경하지 않는다. 상태·우선순위·담당자·일정 자동 변경은 없다.
- 기존 클라이언트가 `question`만 보내면 기존 질의응답으로 동작한다. 새 기능은 `task`, 요약은 `dateFrom`·`dateTo`를 추가한다.

## 검증과 로컬 시연

- 기존 AI 테스트와 새 테스트: 권한 밖 사례 제외, 최대 3건, 빈 결과, 한국어 조사·PC 표현, 입력한 정보를 다시 묻지 않는 기본 질문, 기간, 빈 집계, 모델 장애, 근거 없는 수치·성과 평가, 저장과 API 호환성.
- 프런트엔드 타입 검사·ESLint·프로덕션 빌드 및 실제 화면에서 기간 검증·세 기능·출처 이동을 확인한다.
- 시연 서버에서만 AI를 켜고 기존 가상 데이터 DB를 사용한다. 기본 배포 설정의 AI 비활성화는 유지한다.
- 로컬 시연에는 기존 `qwen3:8b`와 설정에 지정된 `bge-m3`를 사용한다. 누락되어 있던 `bge-m3`는 공식 Ollama 저장소에서 준비했다. 세 지원 기능은 별도 임베딩 모델 없이도 동작한다.
- 최종 자동 검증: AI 104개와 요청 양식 22개를 합쳐 126개 테스트 통과, 프런트엔드 타입 검사·ESLint·프로덕션 빌드 통과. 실제 모델 시연 결과는 조회 결과와 AI 검토 의견을 구분해 확인한다.

기존 백엔드 DB 접속 설정을 준비한 뒤 로컬 AI 시연을 켜는 예(macOS/Linux):

```sh
ollama pull qwen3:8b
ollama pull bge-m3
# src/backend에서 실행
ICTWORK_AI_ENABLED=true bash ./gradlew bootRun --args='--spring.profiles.active=demo'
```
