# 최신 main과 최종 OMNIS 통합

기준: 작업 브랜치 `c28e2a6`, 원격 main `7b18364` (2026-11-08).

## 이력 처리와 기능 보존

main에는 `0738ac4`의 이전 통합 병합과 이를 취소한 `7b18364`가 모두 있었다. 일반 병합만 하면 이미 병합됐던 기능을 Git이 다시 가져오지 않는다. main을 최신화한 후 되돌림을 명시적으로 되돌려 이전 통합을 복원하고, 그 위에 `feat/final-mvp`를 정상 병합했다. 기존 이력을 보존하며 강제 push를 사용하지 않는다.

상황판 한 파일에서 충돌이 났다. 최종 메뉴·통제 단계/주의 현황 카드·업무 통계 상단 조건·원본 브랜딩을 유지하면서 main의 설명 표시 설정도 보존했다. main의 신규 변경 파일 86개 중 79개는 원문과 같고, 7개 화면/스타일 파일은 최종 UI와 함께 합성했다. main의 AI 검증 규칙·QA 계정·시연 자료·설명 표시 설정·AI 대화 목록 높이를 포함한다.

## V43 두 계열의 호환

공식 main 순서를 유지한다.

- V43: `account_show_guides` (기존 main 파일 그대로).
- V44: `operation_systems` (이전 main 통합에서 사용한 파일 그대로).

기존 데스크톱 최종본은 V43에 운영현황 테이블을 만들었다. Electron은 자신이 실행한 로컬 MySQL에서 **정확한 스크립트명·체크섬·성공 상태·테이블 존재**를 확인한 경우에만 호환 처리를 한다. 먼저 전체 DB 논리 백업과 SHA-256을 기록하고, 트랜잭션으로 그 운영현황 이력을 V44의 정식 스크립트/체크섬에 대응시킨다. 이후 한 번의 out-of-order 기동으로 변경하지 않은 main V43 설명 설정을 적용한다. 체계·이력 등 업무 행은 이 과정에서 수정하지 않는다.

백업은 해당 프로필의 `service/backups/`, 처리 기록은 `service/legacy-v43-upgrade.json`에 남는다. 백업 실패·알 수 없는 체크섬·비정상 테이블은 자동 변경을 중단한다. 중단 후 재기동과 적용 완료 후 재기동은 각각 재개/무변경 경로를 사용한다. 일반 main DB는 이력 변경 없이 V44를 적용한다. 서버의 Flyway 검증을 끄거나 임의 repair를 수행하지 않는다. 이 호환 처리는 Electron 소유 로컬 프로필용이며 외부 서버 DB를 자동 수정하지 않는다.

업그레이드한 프로필은 새 실행본을 사용한다. 옛 V43 실행본으로 되돌려야 한다면 모든 앱을 정상 종료하고 현재 자료도 추가 백업한 후, 업그레이드 전 백업을 별도 DB에 복원·확인하는 절차가 필요하다. 원본 DB에 무조건 덮어쓰는 복원은 하지 않는다.

## 검증과 산출물

- `legacy-schema.test.cjs`: 새 DB·main V43·구형 데스크톱 V43·알 수 없는 이력·백업 실패·재개·재기동의 분기 검사.
- `verify-legacy-main-upgrade.cjs`: 성공한 독립 시연 프로필의 복사본만 업그레이드한다. 운영현황·이력 해시, 기존 완료/반려 업무, 백업 SHA, main 설명 설정, 백엔드 전체 테스트와 재기동을 확인한다.
- `verify-main-v43-upgrade.cjs`: 독립 fixture를 main V43까지 만든 뒤 V44로 올리고, 이력 재작성 없이 설명 설정과 운영현황 API가 함께 동작하는지 확인한다.
- `setup-smoke.cjs` 및 `verify-board-roles.cjs`: 신규 설치·업무·결재·등록대장 복귀·전체 메뉴·역할별 권한·상황판 18개 배치·통계 조건/인쇄/엑셀·재시작/정상 종료.

기존 실제 사용자 프로필은 이 병합 시험에서 변경하지 않는다. 검증 근거는 `output/git-main-delivery/`에 기록한다. 새 폴더형 Windows 실행본은 `output/OMNIS-Main-Merged-Windows-x64/OMNIS.exe`이며 resources를 포함한 폴더 전체가 필요하다. 새 설치 프로그램이나 다른 PC 설치 검증을 뜻하지 않는다.

실행 결과: 프런트엔드 108개·호환 분기 6개 검사, TypeScript·충돌 합성 화면 ESLint·WAR 빌드, 신규 프로필 2회 기동/정상 종료·18개 화면 배치·4개 역할 검증이 통과했다. 구형 데스크톱 V43 복사본의 백업·체계/이력 해시·기존 업무·설명 설정·재기동, main V43 fixture의 V44 업그레이드도 통과했다. 백엔드 전체 833개 첫 실행에서 AI 비동기 시험 1개가 30초를 초과했다. 해당 AI 클래스 전체를 독립 재실행해 모두 통과했으며 테스트 시간 제한이나 서버 로직을 바꾸어 통과시키지 않았다. 첫 실행 XML과 로그는 보존하고, 다른 클래스의 성공 결과와 재실행 결과를 구분해 `final-result.json`에 기록했다. 실제 모델 추론 검증과는 구별한다.
