# 기존 OMNIS 디자인 적용과 38개 체계 시연

기준은 `alex50027319/military_project`의 `96d84910367961ce3e0914852663f29e5dad355c`이다. 참조 프로젝트는 읽기 전용으로 두고 `App.tsx`, `style.css`, `ui.tsx`, `StatusChip.tsx`와 실제 Electron 렌더링을 비교했다. 원본의 기존 `out` 빌드를 별도 `OMNIS_E2E_DATA`로 실행하여 사용자 SQLite DB를 건드리지 않고 기준 화면·computed style·실제 렌더링 폰트를 캡처했다. 수정 중인 원본의 추가 기능은 가져오지 않았다.

현재 ictwork의 일반 업무와 기존 OMNIS의 고장·정비 모델은 다르다. 따라서 긴급 업무·업무 진행·업무 접수 대기·지시사항이라는 현재 데이터 의미를 유지한다. 원본에 없는 업무 요청·결재·조직·문서·AI 화면은 원본 공통 디자인을 적용하며 원본과 동일한 업무 내용이나 픽셀 전체 일치를 주장하지 않는다. AI 지원·테마·접힘 등 기존 조작부도 유지한다. 모바일/큰 글씨에서는 원본을 무리하게 축소하지 않고 실제 가용 공간에 맞춘 세 단계 배치를 사용한다.

## 시연 데이터와 사용자 데이터 경계

`desktop/seed-operations-demo.cjs`는 기존 인증·CSRF·`/api/operations`를 사용한다. Java/Kotlin·DB 스키마·마이그레이션·권한·집계·버전 충돌·소프트 삭제 정책은 바꾸지 않았다. 자동 기동·종료 코드와 API 계약도 유지한다.

`legacy-38-v1` 합성 자료는 원본 seed의 7개 분류와 이름 생성 패턴을 사용한다. `DEMO-OMNIS-001`~`038`의 38개로 정상 30·주의 4·점검 2·장애 1·중단 1이며, 정상 운용률은 30/38을 반올림한 79%다. 실제 목록에 다른 체계가 있으면 전체 조회 범위를 기준으로 계산한다. 개별 운용률은 수기 기록 시연값이며 자동 계측값이 아니다.

현재 로그인 계정이 자기 활성 부서를 관리할 수 있는지 확인해 등록한다. 부서 ID를 고정하거나 권한을 변경하지 않는다. 처음 세 체계만 실제 API 상태 변경 두 번으로 이력을 추가한다. 과거 날짜를 조작하거나 가짜 30일 계측을 생성하지 않는다. 재실행은 기존 코드를 건너뛰며 사용자가 편집한 상태·버전·수정 시각도 보존한다. 삭제 이력이 있는 코드 충돌은 강제 재사용하지 않는다. 부분 실패는 manifest에 생성한 ID와 오류를 남기고, 응답 불명확 시 재조회한다.

시연 자료 생성기는 운영현황 API로만 쓰기를 수행한다. 다른 업무·결재·일정·계정·설정을 수정하지 않으며 사용자 DB를 Git이나 실행본 resources에 넣지 않는다. 현재 시연 프로필은 `%APPDATA%\OMNIS Desktop Main`이다. 이 프로필에 등록한 자료는 새 실행본에서도 유지된다. 새 사용자 프로필에는 자동 삽입하지 않는다.

## 검증과 실행

`verify-demo-seed.cjs`는 격리 프로필에서 38개 등록, 5상태, 실제 이력, 반복 추가 0건, 기존 레코드 보존, 검색·페이지 이동·상황판 수치를 검사한다. `verify-legacy-ui.cjs`는 원본의 SVG·실제 폰트·computed style과 새 실행본을 비교하고 사용자 메뉴의 위치·초점 및 주요 업무 화면을 캡처한다. 기존 `setup-smoke`, 메뉴·결재·등록·안내·위험 표시·18가지 배치·권한 검사를 함께 실행한다. 합성 오류 시험은 사용자 프로필과 구분한다.

소스 수정 전후 보호 파일 해시와 원본/수정 WAR의 백엔드 엔트리를 비교한다. UI 변경에 대한 TypeScript·lint·프런트 단위 테스트 및 실제 Electron 기능 회귀 검증을 수행한다. 검증 결과와 시연 자료 manifest는 `output/legacy-ui-demo`에 보관하며 실제 실행한 결과만 완료 보고에 사용한다.

Windows 실행본은 `output/OMNIS-Legacy-UI-Demo-Windows-x64/OMNIS.exe`이다. `resources`를 포함한 폴더 전체가 필요하며 Java/MySQL이 함께 시작되고 일반 창 닫기에서 종료된다. 기존 실행본을 보존한다. 로그인 → 통합상황판 → 운영현황 → 체계명 → 상태·운용률/이력 순서로 확인한다. 다른 PC 설치·실제 체계 계측·실제 AI 모델 추론 검증은 이 작업의 동일 PC 시연 검증과 구분한다.

폰트와 아이콘 라이선스는 실행본의 WAR 내 `/licenses/Pretendard-OFL.txt`, `/licenses/Material-Icons-MIT.txt`에도 포함한다. 검증 후 커밋과 실행본 해시를 기록한다.
