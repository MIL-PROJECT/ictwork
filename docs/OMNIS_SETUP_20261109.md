# OMNIS Windows 오프라인 설치본 검증 (2026-11-09)

현재 main의 UI·시스템 관리자·사용자 등록·LOCAL AI 기능을 production WAR로 다시 빌드해 **OMNIS** 설치 파일과 DVD ISO를 만들었다. 배포 프로그램/설치 화면/바로가기/Windows 앱 표시 이름은 OMNIS다. 기존 Final 프로필의 데이터와 계정 암호를 이어서 사용하도록 내부 데이터 경로와 설치 레지스트리 식별자는 유지한다.

## 배포 파일

ISO 볼륨 이름은 `OMNIS_20261109`다. ISO9660/Joliet 데이터 DVD 이미지이며 설치 파일·설치안내·DVD사용안내·설치 파일 체크섬 4개를 담았다. DVD의 **디스크 이미지 굽기**로 ISO를 기록한 뒤 `OMNIS-Setup.exe`를 실행한다. ISO 자체를 일반 데이터 파일 한 개로 복사하는 방식과 구분한다.

대상은 Windows 10/11 x64다. Electron, Java 17, MySQL 8.0, Microsoft Visual C++ x64 재배포 패키지가 포함된다. 앱 파일은 873개, 약 1.77GB이며 DB/문서 저장 공간이 추가로 필요하다. LOCAL 규칙 기반 질의응답·업무 분석은 포함하지만 Ollama 모델·외부 AI API 서비스는 포함하지 않는다. 설치 파일에는 전자서명이 없다.

## 데이터 유지

원본 `%APPDATA%\OMNIS Desktop Final\service`는 종료 상태에서 복사했다. 원본 DB를 시험 서버로 사용하지 않았다. 원본 275개 파일의 SHA-256은 마지막 검사까지 모두 동일하다. 검증 백업은 `output/OMNIS-Release-20261109/source-backup/service`에 있다.

복사본만 V44에서 V45로 마이그레이션해 배포 SQL을 생성했다. 기존 85개 테이블의 모든 행 지문을 비교했고 기존 행 보존, 외래키, 첨부파일 바이트 검사를 통과했다. 현재 테이블은 90개이며 계정 62, 장비 286, 운영 체계 38, 업무 요청 1533, 업무 처리 건 1616, 일정 188건이다. 기존 계정 암호와 QA 설정을 보존했다.

- **기존 PC**: 프로필 DB가 있으면 포함 SQL을 다시 가져오지 않는다. 원래 프로필을 V45로 마이그레이션하고 기존 업무·계정·암호를 유지한다.
- **새 PC/새 프로필**: 첫 실행에만 포함 SQL과 설정 복사본을 복원한다. 이후 변경된 데이터는 재설치 시 유지한다.
- 표시 이름이 OMNIS여도 데이터 경로는 `%APPDATA%\OMNIS Desktop Final\service`다. 이름을 바꾸거나 삭제하지 않는다.
- 등록된 Final 설치 위치는 그대로 사용하며 새 설치의 기본 프로그램 경로는 `%LOCALAPPDATA%\Programs\OMNIS`다. 기존 OMNIS 바탕화면 바로가기는 교체 전에 프로필의 `shortcut-backups`에 백업하도록 구현했다.
- 제거는 배포 manifest에 기록된 프로그램 파일만 삭제한다. 사용자 프로필과 사용자가 추가한 파일을 재귀 삭제하지 않는다.
- 이전 SQLite 기반 OMNIS와 이 MySQL 기반 설치본 간의 자동 데이터 이관은 지원하지 않는다.

설치 실행은 Electron의 실제 프로세스로 확인했다. UI 검증은 그 설치본이 시작한 Java 서버와 WAR 내 production 프런트엔드를 CUA 브라우저에서 열어 수행했다. Vite 개발 서버 화면으로 대체하지 않았다. 상황판의 96px 요약 카드·운영현황 4행/업무진행 3행, 장비 20행 모두 40px 및 상세의 배정 업무, LOCAL 분석 결과, 개인설정 스크롤 0, 업무 요청 화면, 구성도 목록, 시스템 관리자 화면을 확인했다. 구성도 편집/저장과 문서함 업로드 전 과정을 이번 설치 시험에서 새로 수행한 것은 아니다.

단위 검사 13개와 Windows ANSI 경로 helper 검사(cp949 한글 경로, UTF-8 오류, 표현 불가 문자 거부, 기존 설정 유지)를 통과했다. 검증 스크립트 syntax와 `git diff --check`도 통과했다. 프런트 테스트 113개와 ESLint는 직전 UI 변경 검증 결과이며 이번 설치 작업에서는 프런트 소스를 변경하지 않았다.

마지막 보존 비교에서 격리 시험 계정의 `updated_at` 하나가 일시 암호 변경으로 갱신된 것을 발견했다. 원본/배포 SQL에는 영향이 없었다. 검증 도구가 암호뿐 아니라 이 시각도 복원하도록 수정했고, 실제 설치본에서 다시 일시 변경·종료 후 전체 계정 행이 동일한지 회귀 검사했다.

## 검증 한계와 대상 PC 최종 확인

- 현재 Windows PC의 격리 프로필과 읽기 전용 ISO에서 검증했다. 다른 물리 PC, 실제 DVD 기록/드라이브, 새 Windows VM은 시험하지 않았다.
- 일반 설치의 실제 사용자 레지스트리·시작 메뉴·바탕화면 등록은 TESTMODE에서 실행하지 않았다. 설치 창 이름은 OMNIS로 확인했지만 설치 마법사를 모든 단계 수동 클릭한 시험은 아니다.
- 현재 PC에 VC 런타임이 있어, 런타임 미설치 PC에서의 UAC 설치 분기는 실행하지 않았다. 포함된 런타임의 Microsoft 서명은 확인했다.
- 번들 Java/MySQL의 절대 경로와 최소 PATH로 실행했다. 물리적인 네트워크 단절 시험, 외부 AI/Ollama 호출 시험은 수행하지 않았다.
- 보안 정책이 실행을 막는 환경은 해당 PC 정책에 따른 허용이 필요하다. 제품 서명/신뢰 목록 우회는 하지 않았다.

DVD 대상 PC에서는 실행 중인 OMNIS를 정상 종료하고 데이터 폴더 전체를 백업한 다음 설치한다. 로그인 → 상황판 → 장비 상세 → 시험 업무 저장 → LOCAL AI → 종료/재실행 후 저장 내용 유지 순서로 확인한다. 기존 계정 암호를 사용하며 새 프로필의 시연 계정은 DVD의 설치안내를 따른다. 실제 대상 PC의 확인이 완료되기 전에는 다른 PC 호환성까지 검증됐다고 해석하지 않는다.
